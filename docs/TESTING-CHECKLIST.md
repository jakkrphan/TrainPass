# เช็กลิสต์ทดสอบกับคนและเครื่องจริง

สำหรับ PROGRESS.md หมวด C ข้อ 1–2 และ A3 "ทดสอบบนเครื่องจริง" — ส่วนที่จำลองในเครื่องไม่ได้
(ข้อ 3–4 เรื่องเน็ตหลุดและโหลดสูงมีสคริปต์แล้ว: `npm run test:integration:offline-checkin`, `npm run test:load`)

ติ๊ก `[x]` เมื่อผ่าน · ถ้าไม่ผ่านให้จด: เครื่อง/เบราว์เซอร์, หน้า, ทำอะไร, เห็นอะไร, ภาพหน้าจอ

## เตรียมก่อนทดสอบ

- [ ] เปิดระบบบนเครื่องที่มือถือในวง LAN เดียวกันเข้าถึงได้ (เช่น `npm run build && npx next start -p 3100 -H 0.0.0.0` แล้วเปิด `http://<IP เครื่อง>:3100`)
  - **กล้องบนมือถือต้องใช้ HTTPS** (ยกเว้น localhost) — ใช้ tunnel ที่ให้ HTTPS หรือเซิร์ฟเวอร์ทดสอบที่มีใบรับรอง ไม่งั้นข้อกล้องทั้งหมดทดสอบไม่ได้
  - **ใช้ ngrok กับ `next dev`** (ใช้ได้จริงแล้ว 5 ต.ค.): ใส่โดเมน ngrok ใน `DEV_ALLOWED_ORIGINS` ของ `.env.local` (คั่นด้วยจุลภาค ไม่ใส่ `https://`) แล้ว **restart `next dev`** — ถ้าไม่ restart, Next บล็อกไฟล์ JS ของหน้า (403, log ขึ้น "Blocked cross-origin request") หน้าเปิดได้แต่กดอะไรไม่ได้เลยรวมทั้งปุ่มเปิดกล้อง · ngrok ฟรีเปลี่ยนโดเมนเมื่อเปิดใหม่ ต้องแก้ค่าและ restart ทุกครั้ง · ครั้งแรกกด "Visit Site" ในหน้าเตือนของ ngrok
  - ตั้ง `APP_BASE_URL` เป็นที่อยู่ที่มือถือเปิดได้ ลิงก์/QR ในระบบจึงจะใช้ได้จากเครื่องอื่น
- [ ] บัญชีทดสอบ: admin, ผู้จัด (owner), ผู้ร่วมจัดเต็มสิทธิ์, เจ้าหน้าที่เช็คชื่ออย่างเดียว — ดู README
- [ ] ผู้ทดสอบอย่างน้อย 3 คน: ผู้จัด 1, ผู้สมัคร 1–2 (ใช้มือถือของตัวเอง), เจ้าหน้าที่หน้างาน 1
- [ ] อีเมลยังส่งไม่ได้ (หมวด D) — ผู้สมัครเก็บลิงก์หน้าสถานะจากหน้าหลังส่งใบสมัคร

## 1. ทั้ง flow โดยผู้ใช้จริง

ให้ผู้ทดสอบทำเองโดยไม่บอกวิธี จดจุดที่ลังเล ถามว่า "ต้องกดตรงไหน" หรือเข้าใจผิด

**ผู้จัด — สร้างโครงการ**
- [ ] สร้างโครงการแบบแยกรายวัน 2 วัน (วันที่ 2 ที่นั่ง 1 ที่ เพื่อให้เต็มเร็ว) โหมดอนุมัติเอง
- [ ] ขั้นที่ 3: เพิ่มฟิลด์ชื่อ (แสดงหน้างาน), ประเภทผู้เข้าร่วม (select), ฟิลด์เงื่อนไข "หน่วยงาน" แสดงเมื่อเลือก "ข้าราชการ", ฟิลด์ไฟล์ 1 ช่อง
- [ ] ขั้นที่ 4: รอบเช้า/บ่ายของทุกวัน · ขั้นที่ 5: เพิ่มเจ้าหน้าที่เช็คชื่ออย่างเดียว แล้วเผยแพร่
- [ ] พิมพ์โปสเตอร์ QR หรือส่งลิงก์ให้ผู้สมัคร
- [ ] สร้างโครงการหลักสูตรต่อเนื่อง 3 วันอีกโครงการ (ใช้ทดสอบ "ความต่อเนื่อง" ตอนเช็คชื่อ)

**ผู้สมัคร — บนมือถือของตัวเอง**
- [ ] สแกน QR โปสเตอร์ด้วยกล้องมือถือแล้วเปิดหน้าสมัครได้
- [ ] สมัคร 3 ขั้น: เลือกวัน → กรอกฟอร์ม (ลองเลือก/ไม่เลือก "ข้าราชการ" ดูฟิลด์เงื่อนไขโผล่/หาย) → ยืนยัน
- [ ] แนบไฟล์จากคลังรูป/ไฟล์ในมือถือได้
- [ ] คนที่สองสมัครวันที่ 2 ที่เต็มแล้ว → ได้คิวสำรองและเห็นเลขคิว
- [ ] หน้าสถานะ: บันทึกภาพ QR ได้, แก้ข้อมูล, เปลี่ยนวัน, ยกเลิกบางวัน
- [ ] ปิดเบราว์เซอร์แล้วเปิดลิงก์สถานะใหม่ ยังเห็นข้อมูลเดิม

**ผู้จัด — อนุมัติ**
- [ ] อนุมัติรายคนและหลายคนพร้อมกัน · ปฏิเสธพร้อมเหตุผล → ผู้สมัครเห็นเหตุผลในหน้าสถานะ
- [ ] ยกเลิกคนที่อนุมัติแล้ว → คิวสำรองของวันนั้นมีแบนเนอร์ให้เลื่อนคิว (โหมด manual) แล้วกดเลื่อน
- [ ] เพิ่มผู้สมัคร walk-in แล้วได้ QR ทันที · เปิดไฟล์แนบ · ส่งออก Excel แล้วเปิดใน Excel ภาษาไทยไม่เพี้ยน

**เจ้าหน้าที่หน้างาน**
- [ ] เข้าด้วยบัญชีเช็คชื่ออย่างเดียว → เห็นเฉพาะงานเช็คชื่อ ไม่เห็นคำตอบ/ไฟล์ของผู้สมัคร
- [ ] เลือกรอบ → สแกน QR จากหน้าจอมือถือของผู้สมัคร → สีเขียว + ชื่อ
- [ ] สแกนซ้ำ (เหลือง "เช็คไปแล้ว เมื่อ …"), สแกน QR ของวันอื่น (เหลือง "ไม่ได้ลงทะเบียนวันนี้"), สแกน QR ของคนที่ถูกยกเลิก (แดง)
- [ ] ค้นชื่อแล้วเช็คด้วยมือ · แก้ชื่อที่สะกดผิดแล้วเช็ค · กด "ยกเลิกการเช็คนี้" ภายใน 10 นาที
- [ ] ผู้จัดเต็มสิทธิ์: "อนุญาตเป็นกรณีพิเศษ" คนที่ไม่ได้ลงวันนี้ พร้อมเหตุผล
- [ ] โครงการหลักสูตร: หลังสแกนเห็น "รอบที่ X จาก N · เข้าแล้ว M รอบ"
- [ ] แดชบอร์ดผู้จัดอัปเดตยอดเองภายในไม่กี่วินาทีระหว่างเช็คชื่อ

**หลังจบ**
- [ ] admin เปิดบันทึกการใช้งาน เห็นการอนุมัติ, ส่งออก, เปิดไฟล์, อนุญาตพิเศษ ครบ
- [ ] ถามผู้ทดสอบ: ขั้นไหนงง, ข้อความไหนไม่เข้าใจ, อยากได้อะไรเพิ่ม

## 2. อุปกรณ์หน้างานจริง

ทำบนทุกเครื่องที่จะใช้จริง อย่างน้อย: iPhone (Safari), Android (Chrome), iPad หรือแท็บเล็ต Android, โน้ตบุ๊ก Windows (Chrome และ Edge)

| Android · Chrome | | | | |
| iPad / แท็บเล็ต | | | | |

**กล้อง** (โหมด "กล้อง" ในหน้าเช็คชื่อ)
- [ ] ครั้งแรกเบราว์เซอร์ถามสิทธิ์กล้อง → อนุญาต → ภาพขึ้นและอ่าน QR ได้ภายใน 1–2 วินาที
- [ ] กดปฏิเสธสิทธิ์ → มีข้อความและปุ่ม "ลองอีกครั้ง" · เปิดสิทธิ์จากการตั้งค่าเบราว์เซอร์แล้วใช้ได้
- [ ] ใช้กล้องหลังเป็นค่าเริ่มต้น (ไม่ใช่กล้องหน้า) บนมือถือ/แท็บเล็ต
- [ ] อ่าน QR จากจอมือถือที่ความสว่างต่ำ, จอมีรอยร้าว/ฟิล์ม, และ QR ที่พิมพ์บนกระดาษ
- [ ] สแกนต่อเนื่อง 20 คนติดกันไม่ค้าง ไม่อ่านคนเดิมซ้ำเอง
- [ ] สลับไปแอปอื่นแล้วกลับมา กล้องยังทำงาน

**เครื่องยิงบาร์โค้ด USB / Bluetooth** (โหมด "เครื่องยิง QR")
- [ ] เสียบ/จับคู่แล้วยิงได้ทันทีโดยไม่ต้องแตะช่องรับรหัส
- [ ] ยิงติดกันเร็ว ๆ 10 คน บันทึกครบทุกคนตามลำดับ
- [ ] เครื่องยิงที่ไม่ส่ง Enter ยังเช็คได้เอง
- [ ] แตะที่อื่นบนจอ → แผงเปลี่ยนเป็นสีเหลือง "แตะที่นี่ให้เครื่องยิงพร้อม" → แตะแล้วกลับมายิงได้
- [ ] แป้นพิมพ์ภาษาไทยเปิดอยู่ตอนยิง → รหัสยังถูก (ถ้าเพี้ยนต้องจดรุ่นเครื่องยิงและภาษาแป้นพิมพ์)

**หน้าจอและการใช้งานบนเครื่องจริง**
- [ ] iPhone รุ่นมีรอยบาก/Dynamic Island: ปุ่มและแถบล่างไม่ถูกขอบจอหรือแถบโฮมบัง ทั้งแนวตั้งและแนวนอน
- [ ] แตะช่องกรอกในหน้าสมัคร → หน้าไม่ซูมเอง และคีย์บอร์ดบนจอไม่บังช่องที่กำลังพิมพ์หรือปุ่มถัดไป
- [ ] หมุนจอระหว่างใช้งานหน้าเช็คชื่อ → กล้องกับแผงควบคุมยังอยู่ในจอ
- [ ] แท็บเล็ตตั้งบนขาตั้งทั้งวัน: จอไม่ดับเองระหว่างงาน (ตั้งค่าเครื่อง) และหน้ายังอัปเดตยอดเมื่อกลับมาใช้
- [ ] ตัด Wi-Fi บนเครื่องจริงแล้วสแกน → เห็น "บันทึกไว้ในเครื่อง" → ต่อเน็ต → ซิงก์เองภายในไม่กี่วินาที
- [ ] เปลี่ยนจาก Wi-Fi เป็น 4G/5G ระหว่างใช้งานแล้วยังเช็คได้
- [ ] สแกนต่อเนื่อง 30 นาที: แบตหมดเร็วผิดปกติหรือเครื่องร้อนหรือไม่ (จด % แบตก่อน/หลัง)
